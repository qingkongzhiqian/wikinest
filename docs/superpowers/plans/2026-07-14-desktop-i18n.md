# Desktop Internationalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add persistent English and Simplified Chinese UI selection to the Electron desktop app, defaulting new users to English while keeping AI output language tied to source documents.

**Architecture:** A dependency-free shared i18n module owns locale normalization, flat message dictionaries, interpolation, and fallback. Electron stores `locale` as a top-level preference and exposes it through the existing settings IPC. The web server renders the desktop page for the current locale, while plain `wiki serve` keeps its current Chinese default because Web language selection is outside this release.

**Tech Stack:** Node.js ESM, Electron, electron-store, Express, browser JavaScript, Node test runner.

```js
export const DEFAULT_LOCALE = 'en';
export const SUPPORTED_LOCALES = ['en', 'zh-CN'];

export const MESSAGES = {
  en: {
    'app.settings': 'Settings',
    'app.save': 'Save',
    'app.cancel': 'Cancel',
    'app.close': 'Close',
    'notes.count': '{count} notes',
    'errors.operationFailed': 'Operation failed: {message}',
    'test.englishOnly': 'English fallback',
  },
  'zh-CN': {
    'app.settings': '设置',
    'app.save': '保存',
    'app.cancel': '取消',
    'app.close': '关闭',
    'notes.count': '{count} 篇笔记',
    'errors.operationFailed': '操作失败：{message}',
  },
};

export function normalizeLocale(value) {
  if (value === 'zh' || /^zh[-_]/i.test(value || '')) return 'zh-CN';
  return value === 'en' ? 'en' : DEFAULT_LOCALE;
}

export function createTranslator(locale) {
  const normalized = normalizeLocale(locale);
  return (key, params = {}) => {
    const template = MESSAGES[normalized][key] ?? MESSAGES.en[key] ?? key;
    return template.replace(/\{(\w+)\}/g, (_, name) => String(params[name] ?? `{${name}}`));
  };
}
```

The parity test must deliberately exempt `test.englishOnly` as a fallback fixture, then every production key added by later tasks must exist in both dictionaries.

```js
import { normalizeLocale } from '../src/i18n.js';

export function readLocale(store) {
  return normalizeLocale(store.get('locale'));
}

export function writeLocale(store, value) {
  const locale = normalizeLocale(value);
  store.set('locale', locale);
  return locale;
}

export function syncLocaleToEnv(value) {
  process.env.WIKINEST_LOCALE = normalizeLocale(value);
}
```
