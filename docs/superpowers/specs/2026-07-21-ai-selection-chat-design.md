# AI 选区对话设计

## 目标

在 Wikinest Markdown 编辑器右侧增加 AI 对话侧栏。用户可围绕当前选区连续提问，并将回答安全地替换选区、插入选区后或复制到剪贴板。

## 首版范围

- 仅在编辑模式显示 AI 入口和侧栏。
- 侧栏提供“重写”“扩写”“缩写”“转 Markdown 表格”等快捷指令，也支持自由输入。
- 默认仅发送选区；用户可选择附带整篇笔记。
- 回答以流式方式显示。
- 对话按笔记路径隔离，仅保存在当前应用运行期间，关闭应用后清空。
- 回答提供“替换选区”“插入选区后”“复制”三个操作。
- 应用结果只修改编辑器草稿，不自动保存笔记。
- 继续读取现有 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 和超时环境变量，不增加桌面设置项。

## 架构

### 核心 AI 服务

在 `src/core` 增加专用于编辑辅助的服务。该服务负责：

- 验证消息、选区和整篇笔记的长度；
- 构造稳定的系统提示词，要求模型返回可直接写入 Markdown 编辑器的正文；
- 根据请求决定只提供选区，或同时提供整篇笔记；
- 调用共享 OpenAI 兼容客户端的流式能力。

共享 LLM 客户端增加流式聊天接口，现有非流式 `chat()` 行为保持不变。流式解析兼容 OpenAI `/chat/completions` 的 Server-Sent Events 响应，只向上层暴露文本增量。

### HTTP 接口

后端增加 AI 编辑状态接口和流式对话接口：

- `GET /api/ai/edit/status` 返回 `{ enabled: boolean }`。
- `POST /api/ai/edit/chat` 接收当前会话消息、选区快照、可选整篇正文。
- 成功时返回 `text/event-stream`，发送文本增量、完成事件或公开错误。

API Key 只由 Node 后端读取，任何响应、日志和前端状态都不得包含密钥。

### 编辑器侧栏

编辑区改为可折叠的主编辑器与 AI 侧栏布局。窄窗口下侧栏覆盖显示，避免把 textarea 压缩到不可用宽度。

侧栏包含：

- 当前上下文摘要；
- “附带整篇笔记”开关；
- 快捷指令；
- 当前笔记的临时消息记录；
- 自由输入框、发送和停止按钮；
- AI 回答下方的三个应用按钮。

切换笔记时加载该笔记在内存中的会话；新建草稿使用独立临时会话。关闭侧栏不会清除记录。

## 数据流

1. 用户选中文字并打开侧栏。
2. 前端保存选区快照：起止位置、原始文本和当前草稿标识。
3. 用户点击快捷指令或发送自由指令。
4. 前端将选区、可选整篇正文及该笔记的有限对话历史发送到后端。
5. 后端流式返回文本，前端逐步更新最后一条助手消息。
6. 用户选择应用方式：
   - 替换：仅当原位置内容仍与快照完全一致时执行；
   - 插入：同样验证快照，再插入到原选区末尾；
   - 复制：不依赖快照，随时可用。
7. 应用后触发现有预览更新和草稿未保存状态，用户自行保存。

## 一致性与限制

- 每次请求最多发送 16,000 个选区字符；附带整篇笔记时正文最多 32,000 个字符。
- 对话历史按最近消息裁剪，总输入字符数不超过 48,000。
- 流式请求期间允许编辑，但若选区对应文本发生变化，“替换”和“插入”会拒绝执行并提示重新选择。
- 同一侧栏同一时间只允许一个进行中的请求；用户可主动停止。
- 切换笔记不会把未完成回答写入新笔记；原请求会被取消。
- 模型输出按纯文本处理，通过 `textContent` 展示，不直接注入 HTML。

## 错误处理

- 未配置 LLM 时隐藏或禁用 AI 入口，并给出已有环境变量配置提示。
- 网络错误、超时、模型错误和流中断保留已接收内容，同时显示失败状态。
- 空选区不能发送选区编辑请求。
- 没有完整回答时不显示应用按钮。
- 剪贴板失败时明确提示，不影响回答内容。

## 测试

- 核心测试：提示词、上下文开关、输入裁剪、流式增量及错误转换。
- 服务端测试：状态接口、参数校验、SSE 响应、取消和密钥不泄露。
- 页面测试：侧栏结构、快捷指令、按笔记隔离的会话、流式渲染和停止。
- 编辑安全测试：正常替换、插入、复制，以及选区在回答期间变化时拒绝覆盖。
- 回归测试：现有 AI 整理、标题生成、笔记保存、预览和对象存储同步保持原行为。

## 非目标

- 首版不永久保存或同步 AI 对话。
- 不实现多模型切换、桌面设置中的 API Key 管理或工具调用。
- 不让 AI 自动保存笔记。
- 不实现全文聊天机器人；整篇笔记只作为可选上下文。
