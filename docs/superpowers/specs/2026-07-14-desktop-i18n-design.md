# Wikinest 桌面端中英文切换设计

## 目标

第一版为 Electron 桌面 App 提供英文和简体中文界面。默认语言为英文，用户可以在设置中切换，选择永久保存在本机。切换后刷新当前页面并重建桌面菜单，不重启 App。

## 范围

第一版覆盖：

- 主界面的导航、搜索、列表、文章、编辑、问答、空状态和操作反馈
- 页内设置弹窗与独立设置窗口
- MCP 本地连接弹窗
- Electron 菜单、文件夹选择框和桌面窗口标题
- 日期格式与常见用户可见错误

第一版不覆盖：

- Web 浏览器模式的语言选择
- CLI 输出和服务端启动日志
- MCP 工具名称与描述
- README、环境变量注释和已有 Markdown 内容

## 语言规则

- 支持的 locale 为 `en` 和 `zh-CN`。
- 未保存过偏好时使用 `en`。
- 设置项显示为 `English` 和 `简体中文`，不随当前语言改变名称。
- 缺少翻译键时回退到英文，并在开发环境输出缺失键警告。
- 日期通过 `Intl.DateTimeFormat(locale)` 格式化。

## 技术方案

采用项目内轻量字典，不引入第三方国际化框架。

- 新建共享翻译模块，导出英文、简体中文字典及 `t(locale, key, params)`。
- 英文是完整基准字典，中文字典必须具有相同键集合。
- `src/web/page.js` 从固定 HTML 常量改为按 locale 生成页面，并向页内脚本注入当前字典。
- 动态 toast、confirm、prompt、placeholder 和空状态统一通过翻译键获取。
- `全部`、`未分类` 等内部逻辑状态改为稳定标识符，显示时再翻译，避免切换语言影响筛选。
- Electron 主进程使用同一套语义键重建菜单和对话框文案。
- `desktop/settings.html` 使用 preload 返回的 locale 更新独立设置窗口文案。

## 持久化与切换流程

locale 作为独立用户偏好保存在 `electron-store`，不混入 LLM、Embedding 或 S3 环境配置。

1. 启动时读取保存的 locale；缺失时使用 `en`。
2. 启动本地服务前，把 locale 同步为当前进程的桌面界面偏好。
3. 页面请求按当前 locale 生成 HTML。
4. 用户在设置中选择语言并保存。
5. 主进程写入新 locale，重建应用菜单，并刷新主窗口。
6. 刷新后的页面和设置界面使用新语言；知识库、编辑内容和 AI 配置不受影响。

## AI 语言

界面语言与 AI 输出语言解耦。

- 分类、整理、综述和 RAG Prompt 统一改为英文指令，便于维护。
- Prompt 明确要求输出语言跟随用户文档内容。
- 单篇处理跟随该文档的主要语言。
- 多篇内容使用占比最高的文档语言。
- 问答以检索资料的主要语言为主；资料语言混合且没有明显多数时，以用户问题语言作为决定因素。
- 切换界面语言不会重写笔记，也不会强制改变 AI 输出语言。

## 错误处理

- 常见可预期错误使用稳定错误码，由界面翻译，例如未配置 LLM、未配置上传、认证失败和请求过于频繁。
- 未识别的后端或服务商错误保留原始技术信息，界面在其前面增加本地化的“操作失败”说明。
- locale 值不合法时忽略并回退到英文。
- 保存语言失败时保持当前界面不变，并显示本地化失败提示。

## 测试

- 翻译字典键集合一致，英文和中文均无空值。
- `t()` 支持回退和参数插值。
- 默认 locale 为英文，保存后可以正确读取。
- 页面按两种 locale 生成对应导航、设置和 MCP 文案。
- `全部`、`未分类` 等筛选逻辑不依赖显示语言。
- 保存语言后会重建菜单并刷新主窗口。
- Prompt 使用英文指令，并包含跟随文档语言输出的约束。
- 现有布局、存储、RAG 和 MCP 测试继续通过。

## 验收标准

- 新安装首次打开显示英文。
- 用户可以在设置中切换为简体中文，再切回英文。
- 语言选择在关闭并重新打开 App 后仍然有效。
- 切换不需要重启 App，且不会影响当前知识库或配置。
- 桌面主界面、设置、MCP 弹窗和系统菜单没有明显中英文混杂。
- 中文或英文笔记的 AI 输出语言由内容决定，而不是由界面语言决定。
